02 / THE OPPORTUNITY

The question behind the work.

Researchers, faculty, staff, and public visitors needed to find resources across a growing platform. Content was spread across sections, navigation had become difficult to scan, and the migration had to preserve accuracy and important links.

03 / MY RESPONSIBILITIES

Where I contributed.

  • Implemented the frontend in HTML, CSS, and JavaScript, working from the designer’s UX direction.
  • Migrated and reviewed content across a 30+ page NSF HDR platform.
  • Built shared page structure, responsive navigation, and client-side search.
  • Collaborated with designers and research stakeholders on content accuracy and publishing reviews.

04 / APPROACH & PROCESS

From understanding to action.

  1. 01

    Map the content

    Review legacy pages and identify the tasks of researchers, staff, and public visitors.

  2. 02

    Clarify the structure

    Group related content and implement navigation that makes institutes, resources, publications, challenges, and events easier to reach.

  3. 03

    Build and migrate

    Rebuild pages with shared components, responsive interfaces, search, and support for dynamic content.

  4. 04

    Review and release

    Check content with stakeholders, retain important legacy paths, and publish reviewed updates in stages.

05 / TOOLS & METHODS

The working toolkit.

  • HTML
  • CSS
  • JavaScript
  • GitHub
  • Content migration
  • Responsive design

06 / RESULTS & IMPACT

What the work contributed.

The rebuilt platform brought content for five institutes into one public reference point. Shared navigation and footer components made updates more consistent, while searchable content and preserved legacy links supported discovery and continuity. No measured usability improvement is claimed.

07 / LESSONS LEARNED

What I’m taking forward.

A migration is as much a content and coordination problem as a coding problem. Clear structure, review steps, and reusable components make a platform easier for the next person to maintain.

IMPLEMENTATION DETAIL

A structure built to be maintained.

Legacy platform

Google Sites, content spread across sections, and navigation shaped by program history.

Rebuilt platform

GitHub-hosted HTML, CSS, and JavaScript; shared navigation and footer; searchable pages and clearer routes to resources.

Implementation included client-side search indexing, event and news pagination, challenge status logic, and redirect pages for important legacy paths. The designer led UX direction; I focused on frontend implementation and content migration.

Publishing and handoff

The designer shared the update, I implemented the frontend, and stakeholders reviewed content accuracy before publication. Future work on the NSF HDR platform centers on maintenance and content updates.
